# Max Atlas: External Source Assessment

**Task:** ATLAS-R1. **Fetched:** 2026-09-20 UTC. **Scope:** external research only.

This is a source matrix, not a copied device database, dependency manifest, security audit,
legal opinion, or hardware qualification. No upstream scripts, tests, APKs, or daemons were run.
No repository was cloned. Targeted source and documentation were read over HTTPS; repository
metadata and small tree listings were queried through read-only GitHub/Gitiles APIs.

## Evidence Legend

- **F / fetched:** the specified resource was obtained; fetching alone does not validate its claims.
- **R / README-claimed:** a maintainer's documentation makes the claim; execution was not verified.
- **S / source-verified:** the named source implements the described local behavior. This is not proof of all callers, runtime reliability, or hardware safety.
- **N / not inspected:** no implementation-level assertion is supported by this assessment.
- **D / design:** Atlas recommendation, independently authored, not a measured property of an upstream project.

Confidence is claim-specific: HIGH for the observed source branch or official API contract,
MEDIUM for an architectural lesson supported by limited source, LOW for untested compatibility,
performance, device coverage, and uninspected implementation claims. Stars, forks, commit counts,
README test counts, and plausible-looking measurements do not raise the hardware evidence level.

For each GitHub project, metadata was read from `https://api.github.com/repos/OWNER/REPO` and
the default-branch revision from `https://api.github.com/repos/OWNER/REPO/commits/BRANCH`.
Revision below means the observed branch head, not necessarily a released or stable version.
Unless otherwise stated, license is GitHub's detected license plus README attribution; the
full license file, dependency licenses, and history were **not** inspected.

## Central Source Semantics

### S01: SmartPack

- F/S [GPU.java](https://github.com/SmartPack/SmartPack-Kernel-Manager/blob/c886fc8eae90e74fcc6784813be28feca5b54080/app/src/main/java/com/smartpack/kernelmanager/utils/kernel/gpu/GPU.java): `supported()` aggregates individual feature support. This supports per-feature degradation rather than one model-level supported flag.
- F/S [GPUFreq.java](https://github.com/SmartPack/SmartPack-Kernel-Manager/blob/c886fc8eae90e74fcc6784813be28feca5b54080/app/src/main/java/com/smartpack/kernelmanager/utils/kernel/gpu/GPUFreq.java): stores named path/conversion maps, selects existing entries, caches selections and routes setters to `Control.runSetting`. The constructor falls back to a fixed governor list if no list is read. `hasGovernor`/`hasMaxFreq` are presence-based, not verified effect. The per-path divisors demonstrate why units belong to an interface contract; they do not establish those vendor ABIs today.
- F/R [README](https://github.com/SmartPack/SmartPack-Kernel-Manager/blob/c886fc8eae90e74fcc6784813be28feca5b54080/README.md): custom controller, shell script manager and requests for sysfs path/content/apply details are documented. Those are a maintenance workflow analogy, not authorization for arbitrary runtime controls. The universal-compatibility wording is not a hardware proof.

### S02: Calibrate-SoC

- F/S [WriterRegistry.kt](https://github.com/mayusi/Calibrate-SoC/blob/b7f6b93d66dee1a2dd9dec581feefc7ba47a0bac/app/src/main/java/io/github/mayusi/calibratesoc/data/tunables/writer/WriterRegistry.kt): routing is **per tunable family**, with PServer/vendor carve-outs, ROOT before SHIZUKU, direct-unlocked and Noop cases. The simple `Vendor -> Shizuku -> Root -> Script -> Read-only` prose is not the actual universal ordering.
- F/S [SysfsProber.kt](https://github.com/mayusi/Calibrate-SoC/blob/b7f6b93d66dee1a2dd9dec581feefc7ba47a0bac/app/src/main/java/io/github/mayusi/calibratesoc/data/capability/SysfsProber.kt): read enumeration is separate from a documented Shizuku no-op write probe. CPU policies use `related_cpus` and discovered frequency data; GPU lookup has alternatives. However, `readPolicy` replaces unreadable current caps with table bounds/zero, Adreno does similar substitution, many I/O errors become null, and temperature normalization uses magnitude. Atlas must not inherit those semantics.
- F/S [WriteProtocol.kt](https://github.com/mayusi/Calibrate-SoC/blob/b7f6b93d66dee1a2dd9dec581feefc7ba47a0bac/app/src/main/java/io/github/mayusi/calibratesoc/data/tunables/writer/WriteProtocol.kt) and [RootWriter.kt](https://github.com/mayusi/Calibrate-SoC/blob/b7f6b93d66dee1a2dd9dec581feefc7ba47a0bac/app/src/main/java/io/github/mayusi/calibratesoc/data/tunables/writer/RootWriter.kt): actual code can stop services and chmod nodes. `executeProtocol` reads previous state, writes, then returns `Success` from shell success without a post-write value read; post-hook/seal failures are logged rather than changing that result. Therefore **do not repeat a claim that every writer itself proves readback**. Some other paths may verify; the entire project was not audited.
- F/S [TunableWriter.kt](https://github.com/mayusi/Calibrate-SoC/blob/b7f6b93d66dee1a2dd9dec581feefc7ba47a0bac/app/src/main/java/io/github/mayusi/calibratesoc/data/tunables/TunableWriter.kt): `write` journals previous value then dispatches; it does not add universal readback to RootWriter. `revertAll` walks the journal, with success/skip distinctions that need their own audit. This is partial source evidence for journaling, not a complete atomic transaction guarantee.
- F/R [README](https://github.com/mayusi/Calibrate-SoC/blob/b7f6b93d66dee1a2dd9dec581feefc7ba47a0bac/README.md): ~2,900 tests, alpha status, thermal/non-interference protections and device EACCES-versus-vendor success anecdotes remain maintainer claims. The source tree contains test files, but neither assertion count nor passing status was established. Do not convert source file counts into test counts.

### S03: Kelvin

- F/S [registry.c](https://github.com/Anonym0usWork1221/Kelvin/blob/3d342c79819d24a82c81e10e9447331610a6478f/daemon/soc/registry.c): first matching provider wins, in qcom, mediatek, exynos, generic order.
- F/S [generic.c](https://github.com/Anonym0usWork1221/Kelvin/blob/3d342c79819d24a82c81e10e9447331610a6478f/daemon/soc/generic.c): generic probe requires at least one detected CPU policy. Its provider contains **writers**, not just discovery; Atlas's seam must be narrower.
- F/S [socutil.c](https://github.com/Anonym0usWork1221/Kelvin/blob/3d342c79819d24a82c81e10e9447331610a6478f/daemon/soc/socutil.c): CPU discovery probes `policy0..15`; thermal discovery has a 96-zone index bound; GPU discovery uses token matches then first successful candidate. These are bounded implementation choices, not Linux guarantees or sufficient semantic identity. Prefer bounded actual directory enumeration and ambiguity handling in Atlas.
- F/S [mtk.c](https://github.com/Anonym0usWork1221/Kelvin/blob/3d342c79819d24a82c81e10e9447331610a6478f/daemon/soc/mtk.c): detects PPM user-limit nodes and writes them; restore writes `-1`. Comments refuse thermal table/PPM-disable/debug-NPU/chmod approaches. **The claim that PPM syntax and `-1` are documented/reversible for every target kernel was not independently verified against vendor kernel source.** Never generalize it into a new writer.

### S04: FusionHUD

## Unresolved Claims And Reproduction Notes

- README statements about test counts, device results, ML gains, sensor correctness, thermal safety and benchmark improvements remain unverified unless the specific behavior above is marked S. None is hardware proof.
- For projects without an explicit txt.txt URL (MAGNETAR, GameMode, auto-cpufreq, Kprofiles, Universal Smart Governor), the selected identity is documented, not silently assumed to be the original author's exact source/revision.
- A bounded source inspection cannot establish absence of vulnerabilities, complete rollback, truthful UI in all states, or license compatibility. Especially do not mistake Apache/MIT root metadata for a dependency audit.
- Reproduce a source observation by reading its immutable `blob/REV/PATH` or Gitiles `+/REV/PATH?format=TEXT` URL. Decode Gitiles base64 as data only. No build/install/test invocation is needed or authorized for this research.
- Initial GitHub metadata command expected `jq`, which is not installed; it was replaced by Python's standard-library HTTP/JSON parsing. No local files or external executable code were involved in that fallback.
- Prefer the pinned URLs above for subsequent planning; recheck moving docs and branch heads before implementation. No upstream database or source excerpt has been embedded as executable/product data in this repository.
