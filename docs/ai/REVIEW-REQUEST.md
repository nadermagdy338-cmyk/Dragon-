# REVIEW-REQUEST — حزمة استدعاء نموذج مراجعة

هذا ملف **نقل**، لا مرجع دائم. الغرض: أن يكون إطلاق مراجعة مستقلة **فعلاً واحدًا** من المالك، لا
نسخ جدار نصّي. المرجع الدائم للبروتوكول هو `docs/ai/REVIEW.md`؛ لا تُكرّر قواعده هنا.

---

## ١. لماذا لا يستدعي المنفّذ المراجع بنفسه — مُثبت لا مُفترَض

سأل المالك أن أستدعي النموذج الآخر. الفحص أثبت أن ذلك **مستحيل بنيويًا**، لا ممنوعًا بإذن:

| العائق | الدليل المباشر |
| --- | --- |
| لا أداة تُتيحه | أدوات الجلسة لا تضمّ `spawn_agents` ولا أي اختيار نموذج |
| الـCLI بلا وضع غير تفاعلي | استُخرجت المساعدة **من الملف التنفيذي نفسه** (`~/.config/<الأداة>/<الأداة> --help`، ١٤٠ ميغا): `login` · `--continue` · `--cwd` · `-v` · `-h` فقط — **لا `--model` ولا `--print`** |
| يشترط طرفية حقيقية | في `launcher.js`: `stdio: ['inherit','inherit','inherit']` مع تعليق «the TUI owns the terminal and must see a real tty» |
| **جلسة واحدة فقط** | نصوص الملف التنفيذي تضمّ رسالة «مشغّلة بالفعل»، والجلسة الحالية تملك ملفّ مالك الجلسة بـ`pid 46485` داخل `~/.config/<الأداة>/` |

⇒ الخطوة الوحيدة المتبقية هي **يدك**: بدّل النموذج في المنتقي. كل ما دون ذلك جاهز هنا.

**تحذير صادق**: لا أُوصي باستدعاء واجهة HTTP داخلية ببيانات اعتمادك (`~/.config/<الأداة>/credentials.json`)
لتجاوز هذا — واجهة غير موثَّقة، وتستهلك جلساتك، وقابلة للكسر في أي إصدار. البديل الموثَّق هو المنتقي.

## ٢. الرسالة — الصقها كما هي

### الحالة (أ) — **نفس هذه المحادثة** (المفضَّل: السياق كله موجود)

بدّل النموذج في المنتقي إلى **GPT-5.6 Luna**، ثم أرسل:

```
أنت الآن المراجع المستقل (verifier + safety-reviewer). لا تثق بأي رقم كتبته
الجلسة السابقة، ولا بملخصها — كل رقم تُعيد توليده بأمر.
نفّذ docs/ai/REVIEW.md §2 حرفيًا، ثم §4 (محاولات التكذيب السبع).
قارن كل رقم في جدول §2 بما حصلت عليه أنت واعرض الفرق صراحة.
إن خالف رقم، فالافتراض الافتراضي أن الأمر أو الأداة خطأ — لا أن الكود تغيّر.
لا تصلح شيئًا، ولا تعدّل أي ملف. اكتب حكمك بقالب REVIEW.md §6 فقط.
الملزِم: docs/ai/ENGINEERING-CONTRACT.md و docs/ai/VALIDATION.md.
```

### الحالة (ب) — **محادثة جديدة** (نموذج آخر لا يرى السياق)

أرسل نصّ الحالة (أ) نفسه؛ فهو مكتفٍ ذاتيًا لأنه يحيل إلى `docs/ai/REVIEW.md` وقواعد العقد. الفرق
الوحيد أن المراجع سيقرأ الملفات بنفسه بدل أن يجدها في السياق.

## ٣. ما يُراجَع — نطاق حقيقي لا توصيف

```sh
git status --porcelain                    # نطاق التغيير كاملًا
git diff --stat                           # الأحجام
git diff --check                          # hygiene
```

التصنيف (الحالة: ٢٧ حذفًا · ٢٩ تعديلًا · **٥** إعادات تسمية = ١ `R` + ٤ `RM` · ٢٥ ملفًا جديدًا غير متعقّب):

| الفئة | أمثلة | ما يحتاجه المراجع أن يحكم فيه |
| --- | --- | --- |
| حزمتان منقولتان | `ui/components/` → `ui/component/` · `MtkUtils.kt` → `ui/util/` | أن `0 insertions 0 deletions` = المحتوى لم يتغيّر، وأن كل استيراد يعمل |
| عقد أُعيد تسميته | `CLAUDE.md.bak` → `docs/ai/ENGINEERING-CONTRACT.md` | أن كل مرجع قديم اتُّبع |
| **١٥** ملفًا في `values-ar`/`values-es`/`values-fr` | ترجمة **٤٢٣٧** مفتاحًا (ar +٧٨٥ · fr +١٧٢٦ · es +١٧٢٦) | أن الوسائط لم تُقلب (بوابة `--assert`) — والعدد يُشتق بـ `git status --porcelain \| grep values-` |
| واجهة تبديل اللغة | `AppLanguage.kt` · `AppLanguageSheet.kt` · `locales_config.xml` · `MainActivity.kt` | ADR-27 + مسلك `minSdk 29` |
| أدوات | `tools/code_health.py` · `tools/i18n_coverage.py` · `tools/repo_audit.py` | أن البوابات تفشل فعلًا عند العيب (وليس أنها `exit 0` فقط) |
| مستندات | `docs/ai/*` · `AGENTS.md` · `.planning/codebase/*` | أن كل رقم فيها مُشتق لا منسوخ |

**أعلى القيمة للمراجعة** — ادّعاءات قابلة للتكذيب:

1. **`tools/code_health.py --assert` و`i18n --assert` و`repo_audit` = `exit 0`** — وأن الصحّة أربعة أصفار.
2. **لا مورد مفقود**: ١٨١٩ مرجع `R.string` · ١٥٠٧ مفتاحًا فريدًا · ٠ ناقص.
3. **`--todo de` = ١٧٢٦** (و`ar`/`es`/`fr` = صفر).
4. **الأدوات الثلاث تعطي ناتجًا متطابقًا من الجذر ومن `tools/` ومن مسار مطلق** — يُختبر ببصمة، لا بالنظر:
   `for t in code_health i18n_coverage repo_audit; do diff <(python3 tools/$t.py) <(cd tools && python3 $t.py); done`
5. **بوابة النظافة تفشل عند التراجع فعلًا**: خفّض سقفًا في `tools/code_health_baseline.json` وشغّل `--assert` ⇒ يجب أن يعطي `exit 1`.
6. **مسارات `KernelFlasherScreen`**: شغّل بوابة §5(f) **حرفيًا من `VALIDATION.md`** ⇒ **٨** نتائج فيها وحدها. أي عدد آخر يعني أنك كتبت بوابة أخرى.

## ٤. قاعدتان لا تُخالَفان في هذه المراجعة

1. **افحص أداتك قبل أن تحكم على الكود.** ثلاثة بلاغات كاذبة وقعت في هذه الشجرة والكود كان سليمًا:
   ٤ شاشات «غير قابلة للوصول»، ١٣ مرجع `R.*` «ناقصًا»، ٨٧ «كتابة sysfs». التفاصيل وأسباب الخطأ في
   `REVIEW.md` §1 و§3.2.
2. **افصل ما ثبت عمّا لم يثبت**: **التجميع مُتحقَّق الآن** (2026-09-18) — Android SDK نُزِّل والبناء نجح؛ أعد تشغيل أوامر `VALIDATION.md` §0 بنفسك لا تصدّق الرقم. وما زال **غير مُثبت**: توقيع `release` (سر CI) وسلوك تبديل اللغة على جهاز حقيقي. الصواب أن تقول «compilation verified — signing and device behavior unverified»، لا «كل شيء يمرّ».
